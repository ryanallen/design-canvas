# Design canvas

Every `.html` in a folder on one board. Built, it is one self-contained `canvas.html` that opens from disk and fetches nothing. Served, it edits: select an element, retype it, restyle it, move it, group it, comment on it, and the change is written into that prototype's `.html` at the bytes it touches, nothing else. Served, the server answers the folder's own files the prototypes ask for (pictures, fonts, modules; never hidden ones) and, outside the folder, only the pictures and clips a prototype names there (a design's `../imgs/`), so they show with their paths as written.

It works the way HTML and CSS work: the layers are the DOM, the properties are the element's CSS, elements flow the way the browser lays them out, and only an element that is already positioned moves by `left` and `top`.

On the board, a plain click on a link, button, checkbox or field inside an artboard works it: a link to the web opens in a new tab, a link to another artboard goes to it on the board, a `#` link moves within the artboard. Ctrl or ⌘ + click (or Shift, or Alt) selects it instead, to edit it. A click selects the one element clicked, and a style goes on that element alone; With an element selected, holding Alt over another shows the distance between them in the prototype's own pixels (each side, when one holds the other). Alt + click, Ctrl+Alt+A (Figma's Select matching layers), or **Select every copy** under the toolbar's …, selects every copy of it (and under … too, **Select all with the same fill**, **text color** or **type**, as Figma's, picks everything on the screen that shares it) (the same tag and classes under the same kind of parent), and a style then goes into a rule they all follow. Shift + click adds an element to the selection or takes it out; a style on several picked that way goes on each of them alone, in one edit, alike or not, and they stay selected. A selection that holds text without being text itself (a group, a card) has a Text color, Bold and Italic on the toolbar: every line in it takes the change, over any of its own, in one edit, and the selection stays (Bold and Italic show on when every line already is).

On a phone or tablet, one finger drags the board with any tool that does not draw, two fingers pinch to zoom, and a tap does what a click does. On a narrow screen the layout's links are in the canvas menu under the title, and a comment thread opens over the bottom of the screen.

## Commands

Run from this folder (or give the path to `scripts/canvas.mjs`):

```sh
node scripts/canvas.mjs build  <folder> [--layout canvas.json] [--out canvas.html] [--title t] [--no-measure]
node scripts/canvas.mjs serve  <folder> [the same] [--port 4410]
node scripts/canvas.mjs check  <folder> [--shots <dir>]
node scripts/canvas.mjs accept <folder> <prototype.html>…
```

A person can skip the terminal: **Design Canvas.cmd** (Windows) or **Design Canvas.command** (Mac) asks for the folder and offers build and open, open, check and serve. A built canvas opened from disk in Chrome or Edge edits itself once **Viewing · Edit** is clicked and its folder picked, with no server.

- **build** writes `<folder>/canvas.html`: every prototype inlined, the page's own code inlined, and every comment, edit and board line already in the file kept.
- **serve** builds, then serves it on `http://127.0.0.1:4410/` (the next free port if that one is taken; a `--port` named is used or refused), reachable from this machine only. Edits go into the prototypes; comment, edit and board lines go into `canvas.html`. Each file is written whole or not at all (a hidden file beside it, renamed over it), so a crash or a full disk leaves a prototype or `canvas.html` as it was.
- **check** is the gate: through a real browser it makes each kind of edit, undoes each, leaves and reads back a comment and a sticky note, opens Play, looks at 390 wide, and fails on an error or any request off the machine. Nothing it does is written to disk.
- **accept** says a prototype changed on purpose since its last canvas edit (its build script now carries the edits), so `build` stops refusing it.

Measuring each prototype's height needs a Chromium: `scripts/lib/browser.mjs` finds a Playwright already on the machine (or `CANVAS_PLAYWRIGHT` pointing at a `node_modules` that holds one). Without one, frames are drawn 1440 × 1000 and `check` cannot run.

## What it reads

- **Prototypes**: every `.html` in the folder that is not a `canvas*.html`. A prototype whose screens are `<section class="screen-page" id="…">` is one frame per screen. A folder with none, or one that does not exist yet, builds as a **whiteboard**: one empty page named Board.
- **Layout**: `canvas.json` beside the prototypes, or `--layout`: `{ "title": "…", "pages": [{ "title": "…", "sections": [{ "title": "…", "sub": "…", "groups": [{ "kind": "flat", "frames": [{ "file": "a.html", "hash": "", "label": "a" }] }] }] }] }`. `{ "title", "sections" }` is one page. Group kinds are `flat`, `option` (`letter`, `title`, `info`, `recommended`; the first frame large, the rest under it) and `other`. A frame may carry `crop: "A"` to show one option's column of a comparison board. With no layout, every prototype goes in one grid.
- **Opening on a page**: `canvas.html#page=<id or title>`, such as `#page=summary`, opens on that page, matched without regard to case, ahead of the page last viewed in that browser. A page seen for the first time in a browser shows all of it, unless that would be under 20% and it has more than one section: then its first section and what sits beside it, readable; F or Shift+1 shows everything. Page Down and Page Up go to the next and previous screen on the page, filling the window. After that it opens where it was left. `&screen=<file>` (or `#screen=<file>` alone) opens on that screen instead, zoomed to it, as a Figma link to a frame; **Copy link to this screen** under the toolbar's … puts such a link on the clipboard.
- **Levers**: `<meta name="canvas-levers" content="--accent, --gap">` names the CSS variables shown under Tweaks. A color gets a picker that keeps its alpha; a number gets a slider sized to its unit (0 to 1 in hundredths for a bare fraction, below zero for a negative) and a field for an exact value. A change is written where the prototype's `:root` declares the variable, so the file keeps one value for it. One declared in the `:root` of a stylesheet the screens link from the folder is changed in that sheet, so every screen linking it follows.
- **Fluid**: `<meta name="canvas-fluid">` marks a prototype that reflows to any width.
- **Width**: `<meta name="canvas-width" content="390">` draws a prototype that wide on the board (240 to 3840), measured for its height at that width; without it, 1440. The artboard tool (A) shows Desktop 1440, Laptop 1280, Tablet 834 and Phone 390: a click on the board makes a new prototype of the size chosen, a drag any size, and one not 1440 wide carries this tag. The width on a screen's label (served) changes it for a prototype already there: Desktop, Laptop, Tablet, Phone or a custom width, written as this tag in one edit that Ctrl+Z takes back; the board draws every frame of that file at the new width and measures its height there, and follows the tag whenever the file changes, by an undo or an agent. A click on a screen's label selects the screen, and Properties then shows its Width, set there too (typed, or Desktop, Laptop, Tablet, Phone), and its height as measured; Ctrl+D then copies its file whole to `<name>-copy.html` (the next free name) and places it to the right of the original, past any screen in the way, as do screens taken in a drag box. A page's `<html>`, `<head>` and `<body>` are never copied, removed, wrapped or moved by an edit.
- **Where comments go**: `"comments": "<address>"` in `canvas.json`, or `--comments <address>` on build. Served by node, comments go to the server; editing from disk, into `canvas.html` itself; anywhere else, to that address, or to the hosting site's own `/api/canvas-comments` when none is set.
- **Play**: `"play": true` in `canvas.json` makes the canvas, opened from any website, edit for every visitor with nothing to pick: edits, board objects, artboards and comments are kept in that visitor's browser (localStorage) and seen by nobody else.
- **Links**: `"links": [{ "text": "★ Star", "href": "https://…" }]` in `canvas.json` puts those links at the right of the top bar.

## The lines in `canvas.html`

Everything people do is a line before `</body>`, one JSON event each, never rewritten:

- `<!-- comment {…} -->`: `add` (with `file` and `anchor` when pinned to an element, `box` and `items` when it is about a region of the board, `page` when it is on the board itself, `item` with `dx` and `dy` when it was dropped on a board object (a note, a shape, a section), whose place its pin follows, `x` and `y` being where it was left, `agent: true` when it is work for an agent), `reply`, `resolve`, `delete`, `agent`, `edit` (new words for a comment or reply, taken only from whoever wrote it), `react` (one of 👍 ❤️ 🎉 👀 ✅ on or off for whoever sends it; a message shows each with how many, who on hover). Typing @ and the start of a name in a comment offers everyone who has written there (↑ ↓, Enter or Tab), and an @Name of someone there shows as a mention. A thread offers Edit on what the person viewing wrote, and Delete on that and on everything to the owner, as Figma does; an edited message says so.
- `<!-- edit {…} -->`: who, when, the file, the change in words, and a fingerprint of the file after it. The exact change is the file's own diff.
- `<!-- board {…} -->`: notes, titles, rectangles and ellipses (each with its own text), sections, lines, arrows, pencil strokes, guides, groups (objects sharing a `group` id), stacking order (`z`), pages (a page's `order` is its place in the list, set by Move up and Move down in its menu; Duplicate there makes a page after it with a copy of each of its board objects, groups and arrows between them kept), frames moved by hand, the canvas's own name. A line or arrow with `from` and `to` (a board object's id or a frame's key) is drawn between those two wherever they move; an empty `from` or `to` lets go.

## What a click picks

In a prototype a click picks the element under the pointer (the line), Esc climbs to what holds it and Enter goes in. The canvas menu on the title has **Clicks pick the card** instead, as Figma: a click picks the outermost block holding what is under the pointer, passing over wrappers nearly as big as the page, and each click inside the selection goes one level in (the grid, then the card, then the line), while a drag that starts anywhere inside it moves the selection itself. Hover outlines what a click would pick. The choice is kept in that browser; **Clicks pick the line** goes back. A selected element dragged goes where it is let go, before, after or inside what is there; with Alt held as it is let go, a copy goes there and the element stays. One placed by `position: absolute` or `fixed` moves by its left and top instead, kept straight across or down with Shift held; a handle resizes as drawn, keeping the proportions with Shift held.

A right-click opens the menu of what is under it, never the browser's: in a prototype the element is picked as a click would pick it, unless it is already in the selection (so a right-click on one of several keeps them all), and its menu (the toolbar's **…**) opens there; on a board object it is picked with its group and gets Copy, Paste, Duplicate, Bring forward and Send backward (Ctrl+] and Ctrl+[, past the next object it overlaps), Bring to front and Send to back (with Shift), Group, Ungroup, Zoom to selection, Lock and Delete; on empty board, Paste, Select all, Zoom to fit and the keyboard shortcuts. Text being typed keeps the browser's own menu, for its spelling.

In a prototype the arrow keys nudge a positioned element (absolute, fixed, relative or sticky) 1 px, 10 with Shift, every element selected from its own place, one undo step a press; Alt+arrows move an element in the flow one place in it.

## Typing in place

Enter (or double-click) on a selected text element types in it. Enter while typing goes on in a new element after it, as a text editor does: the same tag and attributes but the id (a paragraph after a heading), never a `<div>` inside the paragraph; Backspace at the start of one Enter made joins it back on (Delete at the end of the one before it too); Tab ends typing, saved, and selects the next part (Shift+Tab the one before). Shift+Enter is a line break inside it; Escape, or Enter in a one-line element, ends typing. Everything typed, however many elements Enter made, is one edit for Ctrl+Z. When the file changes outside the canvas while someone types in it (an agent writing it), the typing goes on and the screen redraws when it ends; the words go into the element typed in, wherever the change moved it in the file, and if the change rewrote that element itself, nothing is written over it: the words are copied, with a hint, to paste where they belong. Every file a page draws carries the version it was drawn from (`data-dc-v` on its `<html>`, never in a download), and the server refuses an edit made from an older one, so a change made in the moment before an agent's write reaches the screen is not written into whatever now stands where its element stood: the screen redraws, and the change is made again. Ctrl+Z and Ctrl+Shift+Z after an outside write undo or redo the edit where it now stands and keep the outside change (`scripts/lib/rebase.mjs`); where the outside change touched that very place, nothing is undone, the hint says so, and the step stays for another try.

## History

**History**, in the canvas's own menu on its title, lists every edit the canvas has recorded, newest first: who made it, when, in which prototype and what it did (the same lines `canvas.html` keeps, read live through `/api/history` when served or editing from disk). **Show** goes to that prototype.

## Flows

**Show flows on the board**, at the top of the Play menu, draws an arrow from each link in a screen to the screen on the page it opens (a link to `other.html` or `other.html#screen`), as Figma draws prototype connections: up from the link, over the tops of the screens, onto the top edge of the one it opens. Kept in that browser until **Hide flows**.

## Commenting in Play

Play shows a screen at full size; ← and → step through the page's screens, and R starts over from the screen it was opened on, as that screen first was. A click on something that does nothing lights up, for a moment, everything on the screen that does (links, buttons, fields), as a Figma prototype shows its hotspots. Where comments can be left, C or the comment button in its header and a click on the prototype pin a comment to the element there, the same anchor a comment made on the board gets, so it shows in both places; the pins for the screen played sit over it and follow it as it scrolls, and a pin opens its thread above Play.

## Layers

The panel's Layers list the page's board objects and frames, and an open frame's elements, each named by its `data-name` or `aria-label`, else what it is and what it says. **Find a layer**, at the head of Layers, lists every board object, screen and element of a loaded screen whose name holds what is typed, flat, each with its screen; a click selects it, Escape empties it. Served, a layer dragged onto another goes before it or after it (by the half it is dropped on), or inside it on the middle of one that holds others: one move in the file. A click on a row selects it; Shift+click selects every row shown from the one clicked last to it (a row inside another taken with it is left to it), Ctrl+click adds a row or takes it out, Alt+click selects every copy. Double-click names a layer in its row (Ctrl+R names the one selected, opening the panel if it is shut), written as `data-name` when Enter is pressed or the row is left (Escape keeps the old name; empty takes it off). The eye on a layer, or Ctrl+Shift+H, hides it (the whole selection when the layer is in it), as `display: none` on the element so Play hides it too, and shows it again, in one undo step; a display of its own (`flex` written by Layout) is kept in `data-display` while it is hidden and comes back with it. A hidden layer's row is dimmed; selected, Properties shows its values as they are when shown, says it is hidden, and has Show.

## Copy and paste

Ctrl+C in a prototype copies every element selected, in page order, as its file has it; Ctrl+V puts them after the element selected (inside it for the page's body). Pasted into the same prototype they stay plain markup, styled by its classes. Pasted into another prototype, each part carries on itself whatever of its look that page would not give it (colors, type, spacing, corners, shadows, layout; never its width or height, so it fits where it lands), found by trying it in place: a page that links the same stylesheet gives it its look by its classes, so nothing is written on it and a change to the sheet still reaches it. An `id` already on the page gets a new one.

Ctrl+Shift+C copies a picture of what is selected as a PNG, as Figma's Copy as PNG, and **Export PNG** under … saves it: the element alone, or the whole screen when its label was clicked, at the size its frame is drawn, twice over for sharpness. A whole screen selected (its label clicked) moves on the board with the arrow keys (Shift: 10), as a Figma frame does; Ctrl+Shift+G and Alt+arrows leave it whole. Selected so, it has **Mode** in Properties' Screen section: Auto, Light or Dark, as a Figma frame's variable mode. Light or Dark switches the screen's own `prefers-color-scheme` rules on or off for it alone, whatever this computer is set to; only what is seen changes, never the file, kept per screen in this browser, and a PNG or PDF of it comes out in that mode. **Export the screen as PDF** under … saves the screen the selection is on as one page, its own width and as tall as its frame is drawn (or the page, if longer), its look as on screen and its words as type, made by the same browser. The server's browser makes it, so it needs a served canvas.

Ctrl+Alt+C copies the selected element's properties and Ctrl+Alt+V pastes them on every element selected, in this prototype or another (both are in the toolbar's **…** menu too): its look alone (fill, gradient, borders, corners, shadow, opacity, text color and type), never its size, place or content, and only what differs is written. Pasted on a box that holds text (a card), the box takes the fill, borders and the rest, and every line of text in it takes the type and text color, over any of its own. A picture fill is left out, since its address as read is the served one. Pasted on every copy of something, it goes into their shared rule.

## Group

Ctrl+G in a prototype wraps the elements selected, side by side in one parent, in a new `div`, and Ctrl+Shift+G takes a wrapper away and keeps what it held. As in Figma, grouping moves nothing: in a grid or a flex row the group is written with `display: contents`, so each part keeps its own cell, and the group is selected and measured by the box around them. **Wrap in flex row**, **flex column** and **grid** under … make a wrapper that lays them out instead. **Shift+A** (Add auto layout, under … too), as in Figma: one element holding others becomes a flex box itself, anything else selected is wrapped in a new one; a row when they sit side by side, else a column, its gap the space already between them less their margins, so nothing moves (in a column the blocks stretch across as before and an inline element such as a button keeps its own width).

## Code tab

The **Code** tab shows the element's own style (editable), then each rule that matches it, strongest first as the cascade ranks them (`!important`, specificity, then order in the file), with every declaration a stronger one overrides struck through, so the value shown unstruck is the one that applies. A rule in the prototype's own `<style>` is editable there, its values as the file writes them and its heading counting the elements it styles: a value changed, added (the empty row under it) or emptied is written into that rule where it stands (`decl` edit, one undo step), so every element the rule matches follows and nothing else does. A rule in a stylesheet the prototype links from its folder (a shared `portal.css`) is editable the same way, its heading naming the sheet and how many screens link it: the change is written into that `.css` file, one undo step, and every screen linking it redraws; so does a change made to the sheet outside the canvas. A rule that styles a locked part stays as it is; the canvas's own overrides, a sheet outside the folder and rules from elsewhere are read only, with + to set a value on the element itself. Then its attributes, what it inherits and from which ancestor, and its source.

## States

Properties has **Default · Hover · Pressed · Focus** above an element's properties. In a state, the element is shown on the board as it looks in that state (every `:hover`, `:active` or `:focus` rule for it applied, the prototype's own and the canvas's), Properties reads those values, and a change is written as that state's rule for the element's id, or else its tag and classes, so Play shows it for real. An element with neither is asked for one. **Motion** (None, Quick, Smooth, Slow) sets how fast it changes into a state and back: a CSS `transition` on the element itself. **Entrance** (Fade, Rise, Pop, Slide, Bounce with a middle keyframe past its place, or Custom: its own first keyframe, from start opacity, scale, turn and X · Y to its resting look, with a middle keyframe of its own X · Y and scale when Middle is on, at 60% of the way unless moved (5 to 95), and a second when Another is on, at 85% unless moved) is how it comes in when the page opens, with a speed (Quick 250, Smooth 450, Slow 800 ms) and a delay in ms to stagger it after what is above it; ▷ plays it again on the board, and Scrub holds it at any moment of it. Leaving Custom takes its own `@keyframes` out of the file. **Stagger** (with two or more siblings of its tag and class, such as a row of cards) gives them all the same entrance, each 60, 120 or 200 ms after the one before, in one edit (the `styles` edit: several elements' own styles at once); Off leaves it on this one alone. ▷ plays every entrance on the screen again. It is an `animation` on the element and the `@keyframes` it names, which the same edit writes into one `<style data-canvas-keyframes>` in the head, so Play and the file shown anywhere run it. Properties reads an element's resting look, never a frame of its entrance.

## Fonts

In Properties, as in Figma, a number field works out a sum typed in it (24*2, 100/4, (16 + 8) / 2, a unit kept), takes ↑ and ↓ (Shift: 10), each step written with its unit kept and the field keeping the keys, and a drag across a number row's label scrubs it (Shift: 10 at a time), written once on letting go. Properties' **Appearance** holds the element's look, each change one undo step. **Fill** is a color, or with ◐ a gradient (Linear, Radial or Angular, two colors and an angle), with ◍ a point mesh (color points dragged on the element, each a radial gradient fading at its spread, plain CSS), or with ◫ a grid mesh (a lattice of 2 to 6 rows and columns whose points are dragged to bend the colors, drawn to a small picture in the element's own CSS, the lattice kept in `data-mesh` to edit again). Every color field has ▦: the screen's levers (custom properties on `:root` holding a color) and the colors it already uses; a lever picked in Fill or text Color is written as `var(--name)`. **Opacity**, **Blend** (the sixteen blend modes) and **Clip content** (overflow cut at the edge and radius). **Radius** is one value or each corner. **Border** reads the side that has one, so a line under a bar shows; its style changes only the sides that have it, and **Border sides** sets each side's width, a new side taking the line's style and color. **Shadow** is each shadow of the element in turn, Drop or Inner, X, Y, Blur, Spread and color; + adds another. **Layer blur** and **Background blur** change only the `blur()` of `filter` and `backdrop-filter`. **Selection colors**, under Appearance, lists every color in what is selected and inside it, named by its uses (Text where words hold it, Fill, Border) and most used first; a color changed there is changed on every element of the selection that has it, in one edit. ⛓ beside Width keeps the element's proportions, as Figma's constrain proportions: its shape as drawn written as its `aspect-ratio`, its height left to follow its width (never shorter than its words); pressed again, the ratio goes and it keeps the height it has. Size shows **Min · Max** width or height under the size where one is set, or after ⇔ beside it, read and written as drawn (padding and border in, as Width is); emptied, a limit written on the element goes and one from its CSS is overruled. Size has **Rotation** in degrees, ↻ a quarter turn, and ⇋ ⇵ (Shift+H, Shift+V) to mirror, as the CSS `rotate` and `scale` properties apart from any `transform`; a turned element's width and height read as laid out. A picture or video has **Fit** (Fill, Fit, Stretch, Original), **Focus** where a crop keeps its middle, and a picture **Alt text**. Text has **Case** (shown upper, lower or title case, the words in the file unchanged), **Truncate** (Lines: past so many lines it stops with an ellipsis), and **Text shadow**, a shadow that follows the letters (`text-shadow`: X, Y, Blur and its color).

Properties › Font lists the fonts the prototype already uses, the ones on this computer, generic families, and, on a served canvas, **web fonts** from Google Fonts. Picking a web font saves the family's latin woff2 files once into the folder's `fonts/<family>/` with `fonts/<family>.css` holding their `@font-face` rules, links that sheet from the prototype's head (a `link` edit, undone like any other) and sets the font. The prototype then holds its own copy, so it shows for everyone who opens it and offline, and a built canvas writes it in with the rest. A font picked from this computer shows only where that font is installed.

## Find and replace

Ctrl+F opens Find: it counts the words wherever they appear in the text of the page's artboards and its board objects, any case; Enter and Shift+Enter step through them, each selected and zoomed to. **Replace all** puts the new words in every place, each in the case of the words it replaces ("Swell" becomes "Surf", "SWELL" "SURF") unless the new words have capitals of their own, through `replaceText` in `scripts/lib/html.mjs`, which changes only text between tags (never a tag, an attribute, a comment, a script, a style or a locked part), on a locked screen nothing; one Ctrl+Z takes all of it back, every screen and board object at once.

## Components

**Make component…** under the toolbar's … (Ctrl+Alt+K) names the selected element a component: it carries `data-component="Name"`, and every element of that name in the file is a copy of it, as is every one on the other screens of a canvas served by node, which take the same change in the same undo step (a screen locked on the board is left as it is). Duplicate one to make another. A style, an attribute, or a part added, duplicated or removed anywhere inside one copy is made at the same place in every copy, and the toolbar says so; text typed into a copy, markup replaced whole in the Code tab, and a copy's `id` stay that copy's own, as does anything in a locked part. The toolbar shows **◇ Name · n** inside a copy (a click selects the copy whole), **Select all n Name** selects every copy, and **Detach from component** makes one copy a plain element again. **Make a variant…** gives a copy a variant name (`data-variant`, as Figma's variants): a style or attribute changed on it then reaches only copies of that variant, while parts added or removed still reach every copy, and the toolbar shows **◇ Name / Variant · n**. **Switch to …** in the toolbar's … menu, on a copy selected whole, gives it another variant: each of its parts takes the style the same part has in a copy of that variant, and it takes that variant's name, its words kept, in one edit. `applyEdit` in `scripts/lib/html.mjs` makes the change in every copy, so an agent's edits through `/api/edit` reach them all too.

## The whiteboard

Every page is a whiteboard, with or without prototypes on it. **Templates…** in the canvas's menu (and "start from a template" on an empty board) puts down a Retro, a Kanban, a Journey map or a Flowchart in the middle of the view (beside everything on the page where that would cover screens or objects), selected, in one undo step. Sticky note (N), text (T), pencil (P: Fine, Marker, Bold or a see-through Highlighter, and its color, on the bar over the toolbar; a picked stroke, line or arrow is made S, M or L on its bar), stamp (E: 👍 ❤️ ⭐ ✅ ❓ 🔥 +1, chosen on the bar over the toolbar; a click puts one down, held by the note, shape or picture under it so it moves with that, and named for who put it; **Stamps, counted** in the canvas's menu lists what has stamps on it, most first, each kind with how many), and under the shape button rectangle (R), ellipse (O), diamond, triangle, section (S), line (L), arrow (Shift+L) and layout guide. Double-click a note, a shape or a section to type in it, or a line or arrow to give it a label, drawn on its middle. A picked note or shape shows a dot beyond each side: dragged onto another object it draws an arrow held by both, and let go on empty board it makes another like the first there, held at that end, ready to type in, all one undo step. A picked shape's bar turns it into another shape in place, its words and the lines bound to it kept, and leaves it an outline (▢) or fills it with a tint of its color (■); a picked line or arrow's bar makes it Straight, Elbow or Curve and gives it no heads (—), a head at its end (→) or heads at both ends (↔), Solid or Dashed, and a line bound to an ellipse, diamond or triangle meets its outline. A note, rectangle or ellipse given more words than it holds grows down to hold them all. A picture (PNG, JPEG, GIF, WebP or AVIF) dropped on the board or pasted with Ctrl+V is saved into the folder's `images/` (the same picture again is the file already there) and placed there at its own size, no wider than 1200; its corner resizes it in proportion (Shift lets the proportions go). `canvas.html` carries the board's pictures inside it (up to 10 MB in all), so one sent alone still shows them. Words pasted with Ctrl+V make a sticky note where the pointer is, grown to hold them, or, with a prototype element selected, a paragraph a line after it (inside it when it holds others). Dropped on a prototype instead, or pasted while one of its elements is selected, a picture goes into that prototype's file: on an `<img>` it takes that one's place (its `srcset` going with the old picture), anywhere else a new `<img>` goes after the element there, or inside it when it holds others; one undo step. Served, or editing from disk; a canvas held in memory, or the published one a visitor plays with, says the picture needs the folder. A title's bar sets its size: S, M, L or XL. A section is a labeled area drawn under everything else: dragged by its label or its border, it carries every object and frame wholly inside it, and a drag anywhere else inside it draws a selection box. Ctrl+Z undoes and Ctrl+Shift+Z (or Ctrl+Y) redoes whatever was done last, on the board or in a prototype, in one history: a board step is everything one action changed (a group dragged, an align, a paste), put back as it was. The arrow keys nudge what is selected on the board 1 px, 10 with Shift (a section with what is inside it; a locked object or a line bound to objects stays), each press one undo step. Ctrl+] brings the objects selected to the front and Ctrl+[ sends them to the back (a `z` on their board lines). Shift+2 zooms to what is selected, on the board or in a prototype, and Shift+1 to everything; Ctrl+= and Ctrl+− (or + and −) zoom the board in and out and Ctrl+0 (or 0) sets it to 100%, never the browser's zoom of the whole page. A board object dragged catches its edges and center on those of other objects and frames it passes, with the line it caught on drawn; Ctrl or ⌘ held lets it go anywhere. Shift held keeps a drag (a screen's too) straight across or straight down, whichever it has gone further along, and keeps a note or shape in proportion as its corner resizes it; Alt held while resizing keeps its middle where it is. A line or arrow begun or ended on a note, shape, section or frame holds on to it and follows it; dragging the line itself lets go. While editing, a drag from empty board with the select tool draws a selection box (with Shift held it adds what it takes in to what is selected), Shift + click adds an object to the selection or takes it out, and Ctrl+A chooses every object and frame on the page (in a prototype, everything alongside the selected element), and **Select matching** (Ctrl+Alt+A, in the right-click menu with how many) every object on the page of the same kind and color as those selected, Tab picks the next object on the page in reading order (Shift+Tab the one before), bringing it into view, and Enter types in the one picked: what is selected moves together, takes one color from its bar, Delete removes its board objects, **Group** (Ctrl+G) makes them one group that a click on any of them picks whole (Ctrl+click picks the one member, as Figma's deep select; a click that does not move, on one of several chosen together by a box or Ctrl+A, takes that one alone) and that moves, colors and deletes as one until **Ungroup** (Ctrl+Shift+G), screens with them (a screen in a group moves with it, from its label too; deleting a group leaves its screens), **Align** lines them up by an edge or center or spaces three or more evenly (Figma's keys: Alt+A, H, D, W, V, S, and Alt+Shift+H or V), **Flip** (Shift+H across, Shift+V up and down, also in the right-click menu) mirrors them within the box round them, a free line, arrow or drawing turned over with them, **Tidy up** (Ctrl+Alt+T, also under Align) puts them in a grid in reading order, a row or a column where they already lie in one, each in a cell as big as the biggest and 40 apart, Ctrl+D duplicates, Alt + drag places a copy where the drag ends, Ctrl+C, Ctrl+V copy and paste (Ctrl+Shift+V, Paste in place, puts the copies exactly where the originals were, on whatever page is open) (a line copied with both the objects it holds holds the copies), **Page** on the bar moves what is selected to another page at the same spot (an arrow between two things that go goes with them; one holding only one of them lets go of it where it is drawn), and **✦ Ask agent** leaves the agent a thread carrying the box and everything in it. Served, every open copy of the canvas redraws when anyone changes the board.

`build` refuses a prototype whose file no longer matches its last edit line, so a rebuild by its own script never drops a canvas edit silently: carry the edits into the script, then `accept`.

Shift+C hides the comment pins on the board, or shows them again (kept in that browser; the comment tool and the Comments tab show them). The **Comments** tab lists the threads, numbered. Over the list, a search finds words in a thread or its replies (or a name), **Resolved** shows the resolved ones too, **Mine** keeps the threads the viewer started, answered or is @named in, and the order is as numbered or **Newest first** by the latest word said; Mine and the order are kept in this browser.

## Working with an agent

From disk, an agent reads the threads straight from `canvas.html`: `parseEvents` and `foldEvents` in `scripts/lib/events.mjs` fold its comment lines, and a thread with `agent: true` is work for it. While `serve` runs, the same is answered over HTTP:

- `GET /api/selection`: what is selected on the board: `file`, `cvs` (source offsets) and each element's source HTML; or, after a selection box, `board` with its `page`, `box`, the board objects inside it in full and the keys of the frames inside it.
- `GET /api/agent`: every open thread marked for the agent, with its file, its anchor (or its `box` and `items`) and its replies.
- `GET /api/board`: every board line, and `board`, the lines folded: `items`, `moved`, `pages`, `name`. To change the board, `POST /api/board` with `{ "event": { "op": "item", "kind": "note", "x": 0, "y": 0, "w": 360, "h": 260, "text": "…", "page": "p1", "name": "agent" } }` (an `id` updates that object), `{ "op": "remove", "id": "…" }`, or `{ "op": "move", "key": "<frame>", "x": …, "y": … }`.
- To answer one: edit the prototype's file (the canvas reloads its frames on its own), then reply on the thread with `POST /api/canvas-comments` and `{ "event": { "op": "reply", "to": "<thread id>", "name": "agent", "text": "…" } }`; resolve it with `{ "op": "resolve", "to": "<id>", "name": "agent" }`.


## Sharing

`canvas.html` is the thing shared: send it or put it on any static host. A host that should take comments answers `GET ?path=<page>` with `{ events }` and `POST { path, event }` with `{ event }`, writing the posted line into the file, at `/api/canvas-comments` on its own site or at the address set with `comments`. A host on another site is called with its cookies (`credentials: include`), so it allows the canvas's origin. [HOSTING.md](HOSTING.md) walks through each way.

## Locks

The owner (whoever edits where the canvas lives: served by node, or its folder on disk) locks what others must leave as it is: an artboard by the padlock in its header, a board object by Lock in its bar or a drag box's bar, a part of an artboard by the padlock in its floating toolbar. A locked artboard or object is not moved, changed or removed until unlocked, and a play-mode visitor puts nothing new over it. A locked part (`data-locked` on an element, and everything in it) is not changed, moved, removed or wrapped, and nothing holding it is retyped or removed. Board locks are `<!-- board {"op":"lock","key":…,"locked":true} -->` lines; part locks are in the prototype's own HTML. `lockedFor(src, edit, { owner })` in `scripts/lib/html.mjs` says why an edit is refused.
